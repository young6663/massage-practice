# Apps Script 部署步驟

這份文件教你把 `apps-script/` 資料夾裡的程式碼，部署成整個練習系統真正在用的後端。
每一步都只有一個動作，照順序做就好。你不需要寫任何程式碼，只需要複製貼上、按幾個按鈕、回答幾個問題。

全程都在你自己的 Google 帳號底下操作，**完全免費**（Google 試算表與 Apps Script 都是免費服務，
即使你的練習群組有十幾個人、用了好幾個月也不會產生費用）。

---

## 你會做的事（總覽）

1. 建立一個新的 Google 試算表。
2. 在這個試算表裡打開 Apps Script 編輯器，貼上 5 個程式碼檔案。
3. 執行 `setupSheets`：自動建立所有需要的工作表，並且塞入題目、題組等資料。
4. 執行 `setAccessCode`：設定同學登入要用的群組通行碼。
5.（選用）執行 `importMembers`：把已經整理好的初始成員名單匯入。
6. 把這個 Apps Script 專案「部署」成一個網址。
7. 把這個網址填進網頁的設定檔，切換成正式後端。
8. 跑一次自動測試，確認一切正常。

---

## 步驟 1：建立 Google 試算表

1. 打開 Google 試算表（sheets.google.com）。
2. 建立一個空白試算表。
3. 把試算表改名為「乙級上岸練習系統」（右上角或左上角的檔名可以點進去改，名稱你可以自己決定，不影響系統運作）。

---

## 步驟 2：建立 Apps Script 專案

1. 在這個試算表裡，打開上方選單「擴充功能」（Extensions）。
2. 點「Apps Script」。
3. 會開一個新分頁，是 Apps Script 編輯器，裡面預設有一個空的 `Code.gs` 檔案。

### 貼上第一個檔案（Code.gs）

1. 在編輯器左側檔案清單，點選 `Code.gs`（預設就有）。
2. 點一下程式碼編輯區，按「全選」（Windows／ChromeOS 是 Ctrl+A，Mac 是 Cmd+A）。
3. 按「刪除」清空。
4. 打開這個專案裡的 `apps-script/Code.gs` 檔案，全選內容，複製。
5. 回到 Apps Script 編輯器，貼上。

### 新增另外 4 個檔案

對下面每一個檔案，重複這幾步：

1. 在編輯器左側檔案清單旁邊，點「＋」（新增檔案）。
2. 選「指令碼」（Script）。
3. 輸入檔名（**不用**打 `.gs`，Apps Script 會自動加），照下面清單分別取名：
   - `SheetHelpers`
   - `Handlers`
   - `Setup`
   - `SeedData`
4. 建立後，編輯區會是空的，全選（Ctrl+A／Cmd+A）、刪除。
5. 打開這個專案裡對應的 `apps-script/SheetHelpers.gs`（或 `Handlers.gs`／`Setup.gs`／`SeedData.gs`）檔案，全選、複製。
6. 貼到剛剛新增的檔案裡。

貼完 5 個檔案後（`Code`、`SheetHelpers`、`Handlers`、`Setup`、`SeedData`），檔案順序不影響運作，不用排序。

### 存檔

1. 按 Ctrl+S（Mac 是 Cmd+S）存檔，或點上方的存檔圖示。
2. 回到「試算表」那個瀏覽器分頁（不是 Apps Script 編輯器），整頁重新整理一次。
   這一步是為了讓試算表選單列出現一個新選單「乙級上岸練習系統」，接下來的步驟都會用到它。

---

## 步驟 3：執行 setupSheets（建立工作表＋塞入題目資料）

1. 確認你在「試算表」那個分頁（不是 Apps Script 編輯器分頁）。
2. 點選單列的「乙級上岸練習系統」。
3. 點「1. 建立所有工作表（setupSheets）」。

### 第一次執行會跳出 Google 的授權確認畫面，照著做：

1. 跳出「這個應用程式需要驗證」的視窗，點「繼續」或「檢查權限」。
2. 選擇你自己的 Google 帳號。
3. 出現「Google 尚未驗證這個應用程式」的警告畫面——這是正常的，因為這是你自己寫的、只有你自己在用的程式，不是別人發佈的公開應用程式。
4. 點畫面上比較不明顯的「進階」連結。
5. 點「前往『乙級上岸練習系統』（不安全）」（名稱依你的 Apps Script 專案名稱而定）。
6. 看到請求的權限清單（存取你的 Google 試算表），點「允許」。
7. 授權完成後會自動回到試算表；如果沒有自動繼續執行，就再點一次「乙級上岸練習系統」選單裡的「1. 建立所有工作表」。

### 確認成功

- 跳出一個對話框寫「工作表建立完成」，點「確定」關掉。
- 下方分頁列會多出 10 個工作表：`participants`、`study_groups`、`group_members`、`questions`、
  `practice_days`、`day_questions`、`question_integrations`、`settings`、`selections`、`practice_sessions`。
- `questions` 工作表應該有 40 列題目；`practice_days` 有 5 列。
- 這個函式可以放心重複執行，不會重複塞資料或壞掉既有資料。

---

## 步驟 4：執行 setAccessCode（設定群組通行碼）

這組通行碼是同學們登入這個練習系統要輸入的，跟 Google 帳號無關。

1. 點選單「乙級上岸練習系統」→「2. 設定群組通行碼（setAccessCode）」。
2. 跳出一個輸入框，輸入至少 6 個字的通行碼（中文、數字都可以，例如「上岸加油2026」）。
3. 點「確定」。
4. 跳出「通行碼已設定完成」，點「確定」關掉。
5. **記住這組通行碼**，之後要口頭告訴同學（不要用文字訊息傳送，也不要寫在任何程式碼、聊天紀錄或公開的地方）。

通行碼不會出現在試算表、程式碼或任何記錄裡，只有雜湊值存在 Apps Script 的「指令碼屬性」中。
如果忘記通行碼，沒有辦法「查詢」，只能重新執行一次 `setAccessCode` 設定新的（新舊通行碼可以不一樣）。

---

## 步驟 5（選用）：匯入初始成員

如果你已經有現成的成員名單（`private/seed.members.json`），可以匯入，不然也可以之後直接在
群組頁（`group.html`）用網頁新增同學，效果一樣。

1. 打開這個專案裡的 `private/seed.members.json` 檔案，全選內容，複製。
2. 點選單「乙級上岸練習系統」→「3.（選用）匯入初始成員（importMembers）」。
3. 跳出輸入框，貼上剛剛複製的內容。
4. 點「確定」。
5. 跳出匯入結果的訊息（新增了幾位成員、幾筆選題等），點「確定」關掉。

這個函式可以放心重複執行：已經存在的 id 會自動跳過，不會重複新增。

---

## 步驟 6：部署成網路應用程式

1. 回到 Apps Script 編輯器分頁。
2. 點右上角「部署」（Deploy）。
3. 點「新增部署作業」（New deployment）。
4. 點齒輪圖示（選取部署類型），選「網頁應用程式」（Web app）。
5. 「說明」欄位可以填「v1」或任何備註（之後每次重新部署可以照版本更新，非必要）。
6. 「執行身份」（Execute as）選「我」（Me）。
7. 「誰可以存取」（Who has access）選「所有人」（Anyone）。
   - 這一步是必要的：一定要選「所有人」，網頁才能呼叫得到；試算表本身不會公開分享，安全性靠通行碼保護（見 `docs/PROJECT_SPEC.md` §6.1）。
8. 點「部署」（Deploy）。
9. 可能會再跳出一次授權確認畫面，照步驟 3 的授權流程做一次（選帳號 → 進階 → 前往（不安全）→ 允許）。
10. 部署完成後，畫面會顯示一個網址，結尾是 `/exec`。點旁邊的複製圖示，把這個網址複製起來。

---

## 步驟 7：把網址填進網頁設定，切換成正式後端

1. 打開這個專案裡的 `assets/js/config.js`。
2. 找到 `appsScriptUrl: ''`，把引號中間貼上剛剛複製的網址，例如：
   `appsScriptUrl: 'https://script.google.com/macros/s/xxxxxxxx/exec',`
3. 找到 `backend: 'local'`，改成 `backend: 'appsScript'`。
4. 存檔。

---

## 步驟 8：跑一次自動測試，確認一切正常

1. 用本機伺服器打開（或直接雙擊）`tests/contract.html?backend=appsScript`。
2. 頁面會出現紅色警語，說明這會在你的真實試算表寫入測試資料（一位「測試同學」、幾筆選題與練習紀錄）；
   測試結束會把這些資料標記取消／作廢／退出，但列本身還在試算表裡，不會自動刪除。
3. 輸入步驟 4 設定的群組通行碼。
4. 點「開始執行測試」。
5. 等待幾秒（Apps Script 每個請求約 1–3 秒，這個測試會呼叫十幾次）。
6. 確認畫面顯示「共 N 項，通過 N，失敗 0」，而且每一行都是 PASS。
   - 如果有 FAIL，先不要繼續正式使用，把錯誤訊息記下來（可以截圖或複製文字）。
7. 打開試算表，可以看到 `participants` 多了一位「測試同學-數字」、狀態是「已退出」（`left`）；
   如果想清乾淨，可以手動刪除這幾列（`participants`、`group_members`、`selections`、`practice_sessions`
   裡跟這位測試同學有關的列），非必要，留著也不影響系統運作。

測試全部通過後，正式上線就完成了：把 `assets/js/config.js` 已經改好的網址部署到 GitHub Pages
（或你原本放這個網站的地方），同學就可以開始使用群組通行碼登入練習。

---

## 之後修改程式碼，怎麼「重新部署」

如果之後 Apps Script 程式碼有更新（例如未來加新功能），網址不需要換掉，同學不用重新設定：

1. 把新的程式碼貼進對應的 `.gs` 檔案，存檔。
2. 點「部署」（Deploy）→「管理部署作業」（Manage deployments）。
3. 找到目前在用的那個部署，點編輯（鉛筆圖示）。
4. 「版本」（Version）選「新版本」（New version）。
5. 點「部署」（Deploy）。
6. 網址不會變，`assets/js/config.js` 不用改。

## 備份

Google 試算表本身就有版本紀錄，不用額外設定：

- 「檔案」（File）→「版本記錄」（Version history）→「查看版本記錄」，可以看到並還原到之前任何一個時間點。
- 「檔案」→「下載」→選 Excel（.xlsx）格式，可以另存一份離線備份，想備份幾次都可以。
- Apps Script 程式碼本身也有版本：編輯器左側「專案版本」可以看到每次「新增部署作業」時建立的版本快照。

## 換通行碼

同學名單不用動，只要重新設定通行碼：

1. 回到試算表分頁，點選單「乙級上岸練習系統」→「2. 設定群組通行碼（setAccessCode）」。
2. 輸入新的通行碼（至少 6 個字），點「確定」。
3. 舊通行碼立刻失效；已經登入過的裝置下次呼叫時會被要求重新輸入通行碼（畫面會顯示「通行碼已失效」的訊息，
   並自動清除裝置上記住的身份）。
4. 把新通行碼口頭告訴同學。

## 疑難排解

| 看到的訊息 | 代表什麼 | 怎麼處理 |
|---|---|---|
| 「找不到工作表：xxx，請先在 Apps Script 編輯器執行 setupSheets」 | 還沒執行過 `setupSheets`，或工作表被改名／刪除 | 回到步驟 3 重新執行 `setupSheets` |
| 「找不到群組資料，請先執行 setupSheets」 | 同上 | 同上 |
| 「通行碼已失效，請重新輸入通行碼」（網頁上） | 通行碼被重設過，或這台裝置存的通行碼是舊的 | 到 `who.html` 重新輸入目前的通行碼 |
| 「嘗試次數過多，請 10 分鐘後再試」 | 短時間內通行碼錯誤次數太多（防止暴力猜測，見 `docs/PROJECT_SPEC.md` §6.1），系統暫時鎖定驗證 10 分鐘 | 等 10 分鐘後再試；不是帳號被鎖，只是這個群組的驗證功能暫停一下 |
| 「系統忙碌中，請稍後再試一次」 | 剛好有另一個人同時在寫入資料 | 重新整理頁面或再試一次即可，資料不會壞掉 |
| Apps Script 編輯器跑函式時出現「無法在這個情境呼叫 SpreadsheetApp.getUi()」之類的錯誤 | `setupSheets`／`setAccessCode`／`importMembers` 這三個函式需要跳出對話框，只能透過試算表選單執行，不能在 Apps Script 編輯器用「執行」按鈕直接跑 | 回到試算表分頁，改用「乙級上岸練習系統」選單執行 |

## 已知限制（跟 `docs/PROJECT_SPEC.md` §6 一致）

- 這不是帳號登入，是「群組通行碼＋選身份」。知道通行碼的人可以用任何成員的身份操作。
  對互相信任的練習同學是可以接受的，如果之後需要更嚴格的保護，要另外設計（例如每人一組 PIN）。
- 試算表本身「誰可以存取」維持不公開（只有你自己看得到），部署出去的只有一個 Apps Script 網址，
  安全性完全靠通行碼；請不要把通行碼寫在任何公開的地方（例如公開的 GitHub repo、公開聊天群組公告）。
