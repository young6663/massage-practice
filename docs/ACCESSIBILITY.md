# 無障礙規格與測試清單

使用者：**全盲**（Windows + NVDA、iPhone + VoiceOver、Android + TalkBack）與**低視能**（放大、高對比、手機）。兩者都是主要使用者，必須同時滿足。目標：WCAG 2.2 AA，並以實際螢幕閱讀器操作為準。

優先順序：可閱讀 → 可操作 → 可理解 → 美觀。

---

## 1. 頁面骨架（每頁都一樣）

```html
<html lang="zh-Hant-TW">
<title>當日選題：第一天 神經類｜乙級上岸練習</title>
<a class="skip-link" href="#main">跳到主要內容</a>
<header>
  <p class="site-name">乙級上岸練習</p>
  <p class="whoami">目前身份：成員甲｜<a href="who.html">切換</a></p>
  <nav aria-label="主要導覽"><ul>…5 個連結，目前頁面加 aria-current="page"…</ul></nav>
</header>
<main id="main" tabindex="-1">
  <h1>…</h1>
  <p id="status" class="status" role="status"></p>   <!-- 唯一的共用狀態訊息區，看得見 -->
  …
</main>
```

- 每頁唯一 `<h1>`；標題層級不跳級（h1 → h2 → h3）。每題用 `<h3>`（或所在層級的下一層），讓 NVDA `H` 鍵、VoiceOver 轉子、TalkBack 標題導覽可以逐題跳。
- `<title>` 格式：「頁面重點｜乙級上岸練習」，頁面重點在前。
- 頁面剛載入時**不移動焦點**，讓螢幕閱讀器從頭讀。例外見 §4。

## 2. 原生元素優先

| 需求 | 用 | 不用 |
|---|---|---|
| 會改變資料的操作 | `<button type="button">` | `div onclick`、`a href="#"` |
| 前往另一頁 | `<a href>` | button + location |
| 熟悉程度（單選） | `fieldset` + `legend` + `input type="radio"` | 自製選單 |
| 弱點（複選） | `fieldset` + `legend` + `input type="checkbox"` | 自製標籤按鈕 |
| 篩選 | `<label>` + `<select>` | 自製下拉 |
| 40 題總表 | `<table>` + `<caption>` + `th scope` | div 排版 |
| 題目清單 | `<ul>`／`<ol>` + `<li>` | 一堆 div |
| 摘要（次數、第一次…） | `<dl>` | |

**不自製 ARIA widget**（tabs、combobox、dialog、menu）。MVP 不使用彈出視窗；確認動作用同頁的確認步驟或 `confirm()`。

## 3. 按鈕與連結名稱

畫面文字可以短，但無障礙名稱要完整，用「看得見的文字＋視覺隱藏文字」組成（不用 `aria-label`，確保語音控制「說出看到的字」可以點到，也方便翻譯）：

```html
<button type="button">選擇<span class="vh">第27題 橈神經麻痺</span></button>
<button type="button">取消選擇<span class="vh">第27題 橈神經麻痺</span></button>
<a href="question.html?q=q27">查看紀錄<span class="vh">：第27題 橈神經麻痺</span></a>
<a href="…">開啟乙級術科練習<span class="vh">：第27題</span></a>
<button type="submit">儲存第27題練習紀錄</button>
```

- 隱藏文字只放「是哪一題」，不寫操作說明（使用者熟練後會嫌長）。
- 同一頁不能出現兩個名稱完全相同但目的不同的控制項。
- 外部連結在同一分頁開啟（手機螢幕閱讀器切分頁容易迷失）；用瀏覽器「上一頁」回來。

## 4. 狀態變化與焦點

共用狀態區 `#status`（`role="status"`，看得見，位於 `h1` 下方）。**只在使用者動作之後**寫入一句話，不重複播報整個畫面。

| 動作 | 焦點 | 狀態訊息 |
|---|---|---|
| 選擇某題 | **留在同一顆按鈕**（按鈕文字就地改成「取消選擇」） | 「已選擇第27題橈神經麻痺。今天已選 2 題，已達建議數量。」 |
| 取消選題 | 留在同一顆按鈕（改回「選擇」） | 「已取消第27題橈神經麻痺。今天還差 1 題。」 |
| 儲存紀錄 | 前往 `question.html?q=q27&saved=1`，焦點移到頁首的確認訊息（`tabindex="-1"` 的段落，不是 role=status，避免重複朗讀） | 「已儲存第27題練習紀錄：第 3 次，大致可以。」 |
| 表單錯誤 | 焦點移到錯誤摘要（`role="alert"`），摘要內每項是連到欄位的連結 | 「有 1 個問題：請選擇熟悉程度」 |
| 抽題 | 焦點留在「抽題」按鈕 | 「抽到第27題橈神經麻痺。」結果區同時更新 |
| 篩選 40 題 | 焦點留在篩選欄位 | 「顯示 12 題」 |
| 載入中 | 不動 | 「資料載入中…」；完成後清空或改為一句結果 |
| 網路／伺服器錯誤 | 不動 | 錯誤區 `role="alert"`：「儲存失敗，資料沒有送出，請再試一次。」 |
| 區塊被隱藏、換成下一步區塊（例如通行碼驗證成功後） | 移到下一步區塊的標題（`tabindex="-1"`），不留在已隱藏區塊裡的按鈕上 | 一句簡短確認句，標題文字會接著被唸出，不用重複說「請做下一步」 |

規則：

- 「資料載入中…」是寫死在各頁 HTML（`h1`、`#status` 之後）的靜態文字，**不是**寫進 `#status` 這個 live region；
  這樣頁面一開啟，畫面還沒渲染完成前，螢幕報讀器照閱讀順序就會唸到，不用額外播報。載入成功或失敗都要
  把這段文字隱藏（`hideLoading()`），失敗時緊接著在 `#error` 顯示錯誤訊息，避免載入完成後畫面還留著「載入中」字樣。
- **處理中狀態不可用 `disabled`**（2026-09-23 里程碑審查決議）：對「正在被聚焦」的按鈕設 `disabled`，焦點會掉到 `<body>`；事後再 `focus()` 拉回，會讓螢幕閱讀器重唸按鈕並和狀態訊息搶話，iPhone VoiceOver 還可能把游標跳回頁首。改為：
  - 設 `aria-disabled="true"`＋加 CSS class（視覺變淡、游標改為等待），click 處理函式在忙碌時直接 return。
  - 選擇／取消、暫停／恢復這類短操作：**處理中不改按鈕文字**；完成後才把文字換成新狀態，結果由 `#status` 播報一次。不再呼叫 `focus()`。
  - 表單送出（會換頁）可把文字改為「儲存中…」，同樣用 `aria-disabled`。
- 狀態改變後若按鈕本身仍存在，就地修改文字；**不要替換整組按鈕**（群組頁的暫停／恢復／退出也一樣）。
- **不整頁重新渲染**：更新只替換變動的節點（按鈕文字、「幾人選」文字），其餘 DOM 保持不動，焦點不會掉。
- 若被操作的元素必須被移除（例如作廢紀錄），焦點移到合理的相鄰位置（該區標題或下一項）。
- 同一時間只寫一則訊息；新訊息覆蓋舊訊息。寫入前先清空再設定（`textContent = ''` 然後下一個 tick 寫入），讓相同內容也會被再唸一次。
- 不使用自動輪播、自動更新、計時消失的訊息。

## 5. 語音

- 本系統**不自己朗讀**。完全交給 NVDA／VoiceOver／TalkBack。
- 若未來加入網站朗讀：預設關閉、可開關、有播放／暫停／停止按鈕、不搶焦點、不與螢幕閱讀器重複。

## 6. 表單（新增紀錄）

```
熟悉程度（必填）   fieldset/legend + 4 個 radio：很不熟／還要再練／大致可以／可以上場
這次的弱點（可複選） fieldset/legend + 9 個 checkbox
這次卡在哪裡？     label + textarea
備註              label + textarea
練習日期           label + input type="date"（預設今天）
[儲存第27題練習紀錄]
```

- `required` 欄位在 legend 文字寫「（必填）」；錯誤欄位加 `aria-invalid="true"` 與 `aria-describedby` 指向錯誤說明。
- 不用 placeholder 當標籤。
- 送出中按鈕改為「儲存中…」並 `disabled`，避免重複送出；完成或失敗後恢復。

## 7. 低視能：字體與版面

- 根字級不寫死：`html { font-size: 100%; }`。正文 `1.125rem`（18px 基準），行高 1.6。主要資訊不小於 `1rem`；不用 12–13px 小字。
- 標題：h1 `1.75rem`、h2 `1.375rem`、h3 `1.2rem`，粗體。
- 全部用 `rem`／`em`；容器不設固定高度；不用 `overflow: hidden` 裁切文字。
- 單欄版面，內容最大寬度約 `42rem`，置中；左右留白至少 `1rem`。
- 段落、清單項目之間要有明顯間距；每題之間用實線分隔，不用大量陰影卡片。
- 不用 icon 單獨表達意義；若有 icon 必有文字。
- 不使用動畫、轉場、玻璃效果；`prefers-reduced-motion` 下也不會有任何動作。

## 8. 色彩與對比（已計算）

| 用途 | 前景 | 背景 | 對比 |
|---|---|---|---|
| 正文 | `#1a1a1a` | `#ffffff` | 17.4:1 |
| 次要文字 | `#4a4a4a` | `#ffffff` | 8.9:1 |
| 連結、主色文字 | `#0a4a8f` | `#ffffff` | 8.8:1 |
| 主要按鈕 | `#ffffff` | `#0a4a8f` | 8.8:1 |
| 按鈕框線、輸入框 | `#5c5c5c` | `#ffffff` | 6.7:1 |
| 錯誤訊息 | `#a3161a` | `#ffffff` | 7.8:1 |
| 成功訊息 | `#1d5a2c` | `#ffffff` | 8.2:1 |
| 熟悉度：很不熟 | `#8b1a1a` | `#fdecec` | 8.1:1 |
| 熟悉度：還要再練 | `#6b4200` | `#fff4d6` | 8.0:1 |
| 熟悉度：大致可以 | `#1d5a2c` | `#e7f4ea` | 7.3:1 |
| 熟悉度：可以上場 | `#0a4a8f` | `#e8f0fb` | 7.7:1 |
| 尚未練過 | `#3d3d3d` | `#eeeeee` | 9.4:1 |

- 熟悉程度**一定顯示文字**，顏色只是輔助；標籤加 `1px solid currentColor` 框線，在 Windows 高對比模式（forced-colors）下仍看得出範圍。
- 「已選擇」除了底色，還要有文字「你已選擇」。
- 按鈕一律有看得見的框線，不只靠底色。
- **動作與前往要看得出差別**（里程碑審查決議）：
  - 會改資料的主要動作（選擇、儲存、抽題）：實心主色按鈕。
  - 「取消選擇」、暫停、退出：白底＋主色粗框線（2px）按鈕，文字主色。
  - 前往另一頁的連結（查看紀錄、開啟術科、留下紀錄）：做成大觸控範圍的**文字連結**樣式（底線、主色、無實心底），不要和按鈕長得一樣。
- 已選擇的題目：該題區塊左側加 `0.375rem` 主色實線，「你已選擇」一行加粗；文字仍是主要資訊。
- 修改配色時，必須重新計算並更新本表（`tests/contrast.py`）。

## 9. 焦點

```css
:focus-visible {
  outline: 3px solid #000;          /* 對白底 21:1 */
  outline-offset: 2px;
  box-shadow: 0 0 0 6px #ffd400;    /* 黃色外環，對黑框 14.7:1，在深色按鈕上也看得到 */
}
```

- 禁止 `outline: none`（除非同時提供等效的可見焦點）。
- 焦點順序 = 畫面閱讀順序；不使用正數 `tabindex`。
- 焦點不會被固定頁首遮住（MVP 不用固定頁首；若日後使用，加 `scroll-padding-top`）。

## 10. 觸控與手機

- 所有按鈕、連結、表單控制項的可點範圍至少 `2.75rem × 2.75rem`（約 44px）；radio／checkbox 整個 label 可點，且 label 高度達標。
- 相鄰按鈕間距至少 `0.5rem`。
- 不依賴 hover、長按、拖拉、滑動手勢。
- `<meta name="viewport" content="width=device-width, initial-scale=1">`，**不得**禁止縮放。

## 11. 縮放與重排

- 瀏覽器 200% 縮放：所有內容可讀、所有功能可操作、不用水平捲動就能找到功能。
- 320 CSS px 寬（等同 400% 縮放）：單欄重排，除了 40 題總表外不出現水平捲動。
- 40 題總表：包在 `<div class="table-wrap" role="region" aria-label="40題總表" tabindex="0">` 內可水平捲動（資料表格屬 WCAG 例外），第一欄（題號題名）用 `<th scope="row">`。
- 文字間距調整（行高 1.5、字距 0.12em 等）後內容不被裁切。

## 12. 各頁重點

- **首頁**：h2 依序為「今天：第一天 神經類」「下一步」「我的選題」「我的弱題」「所有題組」。第一個 h2 區塊就要回答今天練什麼、還差幾題。
- **當日選題**：開頭一句「建議每人選 2 題，你已選 1 題」。題目清單前加一個看得見的 `<h2>本日題目</h2>`（避免 h1 直接跳到每題的 h3，造成標題層級跳級）。每題 h3「第27題 橈神經麻痺」，下方依序：「你已選擇／你未選擇」、「2 人選擇：成員甲、成員乙」（0 人時寫「還沒有人選」）、你最近一次熟悉程度、按鈕列。
- **單題紀錄**：`<dl>` 摘要 → 「練習歷史」`<ol>`，每筆「第 N 次｜9月23日｜大致可以」＋弱點＋卡在哪裡＋備註。已作廢者標「已作廢」且不計次。
- **我的弱題**：每題顯示原因文字（§4.3 規格）。空狀態要說明「目前沒有弱題」而不是空白。「尚未練過」只顯示題數＋連到 40 題總表（帶 `status=unpracticed`）的連結，不在本頁重複列出全部題目；「依狀態查看」預設不選任何狀態、不列清單，使用者選了狀態才顯示，避免和「尚未練過」與 40 題總表重複列出同一份清單。
- **40 題總表**：`<caption>` 說明目前篩選條件與題數。
- **模擬抽題**：範圍用 radio；結果區 h2「抽題結果」，之後是題號題名與兩個連結（開啟術科、留下紀錄）。

## 13. 測試清單

每個 Phase 結束時由 qa-tester 執行，重大里程碑由 accessibility-reviewer 覆核。

### 鍵盤（Windows 瀏覽器，不碰滑鼠）
- [ ] Tab／Shift+Tab 可到達所有互動元素，順序合理
- [ ] 每個焦點位置都清楚可見
- [ ] Enter 觸發連結與按鈕；Space 觸發按鈕、勾選 checkbox
- [ ] 方向鍵在同一組 radio 間移動
- [ ] 沒有鍵盤陷阱
- [ ] 選題／取消後焦點仍在該按鈕
- [ ] 表單錯誤後焦點移到錯誤摘要，連結可跳到欄位

### NVDA（Windows，Chrome／Edge／Firefox）
- [ ] 「跳到主要內容」可用
- [ ] H 鍵可逐題跳；標題層級合理
- [ ] 按鈕名稱包含題號題名
- [ ] 選題、取消、儲存、抽題、篩選的結果會被唸出一次，不重複
- [ ] radio、checkbox 的群組名稱（legend）會被唸出
- [ ] 表格標題與欄名正確

### VoiceOver（iPhone Safari）與 TalkBack（Android Chrome）
- [ ] 左右滑動可依序讀完頁面，無漏讀、無無意義元素
- [ ] 轉子／閱讀控制可用標題導覽
- [ ] 雙點可操作所有按鈕
- [ ] 狀態訊息會被播報
- [ ] 日期欄位可輸入

### 低視能
- [ ] 200% 與 400% 縮放（或 320px 寬）版面正常，不裁切
- [ ] 系統字級調大（手機大字體）不破版
- [ ] Windows 高對比模式（forced-colors）按鈕邊界、焦點、熟悉度標籤仍可辨識
- [ ] 所有配色符合 §8 表格；新增顏色已計算
- [ ] 沒有只靠顏色表達的資訊

### 自動檢查（輔助，不能取代實測）
- [ ] HTML 驗證無結構錯誤（重複 id、缺 label）
- [ ] axe 檢查無 critical／serious（在 Claude 內建瀏覽器注入 axe-core 執行）
