## 2. 問題清單

### 阻擋（0 項）

無。

### 嚴重（7 項）

#### S1 who.html：通行碼確認成功後，焦點掉到頁面最上方
- **元素**：`#access-form` 的「確認通行碼」按鈕。`revealAfterAccessVerified()` 會把整個 `#access-section` 設成 `hidden`，而焦點正停在這個區塊裡的按鈕上。
- **實測**：送出 1234 後，下一個畫面更新時 `document.activeElement` 變成 `BODY`。
- **使用者會遇到**：NVDA 唸出「通行碼正確，請選擇你是誰。」，但瀏覽游標已回到文件開頭，按下方向鍵會從「跳到主要內容」、「乙級上岸練習」重新唸，要再往下找才到「你是誰？」。iPhone VoiceOver 的游標所在元素消失後，通常會跳回頁首或停在不明位置。這是全新使用者的第一個畫面。
- **修法**：`#identity-section` 的 `<h2>你是誰？</h2>` 加 `tabindex="-1"`，reveal 之後對它呼叫 `focus()`；狀態訊息縮成「通行碼正確。」（標題會接著被唸出，不用再說「請選擇你是誰」）。建議在 ACCESSIBILITY §4 表格補一列：「區塊被隱藏、換成下一步區塊時，焦點移到下一步區塊的標題」。

#### S2 全站：載入資料時畫面與報讀都沒有任何提示
- **元素**：每頁 `init()` 在 `await getBootstrap()` 期間，主要內容都是 `hidden`，也沒有載入中文字（搜尋整個專案都找不到「載入中」）。ACCESSIBILITY §4 規定要顯示「資料載入中…」。
- **實測**：day.html 載入後 50ms，`main` 只有「當日選題」幾個字，沒有其他內容。
- **使用者會遇到**：換成 Apps Script 後端後，每次載入約 1–3 秒，冷啟動會更久。NVDA 開頁時唸完「當日選題 標題1」就到文件結尾；VoiceOver 往右滑也滑不到東西。使用者會以為頁面是空的，或資料不見了。低視能使用者看到的是只有標題的白畫面。
- **修法**：在各頁 HTML 的 `h1`、`#status` 之後放一段靜態的 `<p id="loading" class="field-hint">資料載入中…</p>`（不要放在 live region 裡，頁面載入時也不要寫入 `#status`），載入成功或失敗時設成 `hidden`。這段在 HTML 原始碼裡，開頁時就會照閱讀順序被唸到，也不違反「只在使用者動作後播報」。建議在 `dom.js` 加共用的 `hideLoading()`。

#### S3 record.html：欄位錯誤沒有 `aria-invalid`／`aria-describedby`，欄位旁也沒有錯誤文字
- **元素**：`showFieldErrors()` 只產生錯誤摘要，沒有標記欄位（整個專案找不到任何 `aria-invalid`）。這違反 ACCESSIBILITY §6。
- **使用者會遇到**：使用者從摘要連結跳到「很不熟」選項後，NVDA 只唸「熟悉程度（必填） 分組 很不熟 選項按鈕 未選取」，沒有「無效」，也不會再說錯在哪裡；用 Tab 走到日期欄也一樣。低視能使用者捲到欄位時，旁邊看不到紅字。
- **修法**：
  - 熟悉程度（radio 群組）：在 `<legend>` 內追加 `<span class="field-error">錯誤：請選擇熟悉程度</span>`。legend 文字 NVDA、VoiceOver、TalkBack 都一定會唸；fieldset 的 `aria-describedby` 則不一定。
  - 日期：`<input>` 設 `aria-invalid="true"`，並用 `aria-describedby` 指向欄位下方的 `<p id="practiced-at-error" class="field-error">`。
  - 在欄位 `change`／`input` 時，以及送出成功前，移除錯誤文字與 `aria-invalid`。
  - `.field-error` 用 `#a3161a`，並加粗或加左框線，不要只靠顏色。

#### S4 錯誤與結果只寫在頁首，200% 縮放或手機上看不到
- **實測位置**：
  - record.html：日期填未來日期時，伺服器會回「練習日期不能晚於今天。」。這時畫面捲在送出按鈕附近，`#error` 位在 `top = -173px`，在視窗外。
  - group.html：顯示名稱空白就按「新增同學」時，錯誤訊息在輸入框上方約 620px。
  - draw.html：範圍選「我的弱題」但沒有弱題時，說明只寫在頁首的 `#status`，結果區維持隱藏。
  - group.html 三個表單的成功訊息也都只在頁首。
- **使用者會遇到**：螢幕報讀器使用者聽得到（`role="alert"`／`status`），但低視能使用者放大後按下按鈕，只看到按鈕文字閃成「儲存中…」又變回來，畫面其他地方都沒變，會以為沒反應而一直重按。
- **修法**：
  - record：`<input type="date">` 加 `max`（今天）先擋掉；伺服器回傳的欄位類錯誤（日期、字數）改走錯誤摘要＋S3 的欄位錯誤，不要只用 `showError`。
  - group／who 的姓名欄：欄位下方顯示錯誤文字，並用 `aria-describedby`＋`aria-invalid` 連到輸入框（焦點本來就會移到欄位）。
  - draw 空題庫：把說明文字放在結果區（區塊顯示，內容寫原因），`#status` 仍播同一句。結果區不是 live region，所以只會唸一次。
  - 群組表單的成功訊息：在各表單按鈕旁加一行看得見的結果文字（非 live），`#status` 照常播報。

#### S5 全站：錯誤區 `role="alert"` 平常是 `display:none`，iPhone 上可能不會唸（推測）
- **元素**：`base.css` 的 `.error:empty { display: none; }`，而 `#error` 是 `role="alert"`。錯誤一寫入，這個元素就從「不在無障礙樹」變成「出現並帶有內容」。
- **使用者會遇到**：Chromium＋NVDA 通常會把「新出現的 alert」唸出來。Safari＋VoiceOver 對「本來 display:none、之後才出現的 live region」支援不穩，可能完全不唸。例如 who.html 沒選身份就按「進入」，可能什麼都聽不到。
- **修法**：不要用 `display:none` 隱藏空的錯誤區，讓它一直留在無障礙樹裡，只把外觀收起來：
  ```css
  .error:empty { border: 0; padding: 0; margin: 0; background: none; }
  ```
  `.error-summary` 另外靠 `hidden`＋`focus()`，不受影響。請用第 3 節 VoiceOver 步驟 2 確認。

#### S6 all.html：「題號」欄位沒有套用樣式，字只有 13.3px
- **元素**：`#filter-number` 是 `type="number"`，但 CSS 只選到 `input[type="text"]`、`input[type="date"]`。
- **實測**：字級 13.33px、高 21px，框線是瀏覽器預設的 inset 灰框。同一排的 select 是 18px、44px 高。
- **使用者會遇到**：低視能使用者看到一個特別小的框，點不準；手機上也不到 44px。`type="number"` 在 NVDA 會唸成「微調按鈕」，按上下鍵會直接改數字並觸發篩選。
- **修法**：改成 `<input type="text" inputmode="numeric" pattern="[0-9]*" maxlength="2">`，並把 `input[type="number"]` 一起加進 CSS 選擇器（保險）。篩選改在停止輸入約 500ms 後，或 `change` 時才執行並播報（見 A1）。

#### S7 weak.html：同一份 40 題清單預設會出現兩次，約 160 個連結擋在篩選欄前面
- **元素**：「尚未練過」列出每一題未練的題目；「依狀態查看」預設「全部狀態」又把 40 題全部列一次。實測 p01 全部未練時，`main` 裡有 161 個連結。「尚未練過」的每一項是 `<p>`，不是標題。
- **使用者會遇到**：新同學（還沒練過任何題）打開「我的弱題」時，NVDA 要按 80 次以上 Tab 才到「選擇狀態」下拉選單。用 H 鍵也跳不過「尚未練過」這 40 項。VoiceOver 要一路滑過 80 題。
- **修法**（擇一，建議第一種）：
  1. 「尚未練過」只顯示「共 N 題尚未練過」，加一個連結「在 40 題總表查看尚未練過的題目」（`all.html?status=unpracticed`，all.js 讀取這個參數並預選篩選條件）。
  2. 「依狀態查看」預設不列清單，改成使用者選了狀態才顯示；或整段刪掉，因為它和 40 題總表的功能重複。

## 3. 手動測試腳本（只測自動化無法確認的部分）

事前準備：瀏覽器清除本網站資料；通行碼 1234。可以的話，改用 Apps Script 後端測，才能體會真實的載入時間。

### 3.1 Windows＋NVDA（Chrome 或 Edge）

1. 開 who.html，輸入 1234 並按 Enter。記下 NVDA 唸了什麼；接著按一次向下鍵，記下唸出的是哪個元素（修正前預期會回到頁首，對應 S1）。
2. 不選任何人，直接按「進入」，確認「請先選擇你是誰」只唸一次。
3. 選「成員甲」進入首頁。在資料還沒出現前，NVDA 是否唸到任何內容？資料出現後，按 H 鍵能否跳到「今天：第一天 神經類」（S2）？
4. 在 day.html 對某題的「選擇」按 Enter。記下唸出的所有內容和順序（預期：按鈕新名稱「取消選擇第N題…」＋狀態句），確認沒有同一句唸兩次。
5. 在同一顆按鈕上快速連按兩次 Enter，確認只選了一次，第二次是否聽到「不可用」或「暗淡」之類的提示。
6. 進 record.html，什麼都不填就按儲存。數一數「有 2 個問題」唸了幾次（A9：唸兩次就要拿掉 role=alert）。
7. 在錯誤摘要按 Tab 到「請選擇熟悉程度」，按 Enter，確認 NVDA 唸出「熟悉程度（必填） 分組 很不熟 選項按鈕」。
